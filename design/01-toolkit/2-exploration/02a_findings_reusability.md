# 02a. "재사용성"의 재정의

> 사이 문서. 02 스택 → 03 엔진으로 넘어가면서 요구사항의 뜻이 바로잡힌 과정.

## 1차 답의 형태와 그것이 빗나간 이유

"이 스택을 단계별로 적용 가능한 재사용성 있는 장치로 만들 수 있는가"라는 질문에 처음 낸 답은 **저장소 구조**였다.

```text
korean-quality-stack/
├── manifest.yaml     # 층 활성화, threshold
├── policy/           # 블록 + 렌더러
├── skills/           # 업스트림 vendor
├── gates/            # CLI
├── evals/
├── adapters/         # claude-code, codex, git
└── skills.lock
```

여기에 sidecar report, exit code 계약, 정책 블록 합성, 업스트림 lock, 단계 활성화 gate라는 다섯 가지 설계 결정을 붙였다.

이 답은 "재사용"을 **설치와 이식**으로 해석한 것이다. 하네스가 바뀌어도 저장소를 옮겨 hook을 다시 걸면 된다는 뜻에서의 재사용.

그런데 요구사항은 달랐다.

> 재사용성이란 이것이 모듈·엔진처럼 **에이전트에게 기능으로서 제공 가능**함을 말한 것. 서브에이전트에게 해당 기능을 적용시켜 검토를 맡긴다거나, 에이전트의 사고·프롬프트에 적용한다거나. 엔진에서 단계별로 적용 가능하고.

즉 재사용의 주체가 **사람(설치자)이 아니라 에이전트(호출자)** 였다. 저장소를 옮기는 문제가 아니라 에이전트가 런타임에 부를 수 있는 인터페이스의 문제였다.

## 다시 정의된 재사용성

한국어 품질 스택이 다음 세 방식으로 에이전트에게 노출된다.

| 방식 | 뜻 | 예 |
|---|---|---|
| 검토 위임 | 서브에이전트에게 "이 기능으로 검토해라" | 리뷰어 에이전트가 진단과 gate를 수행하고 report를 반환 |
| 생성 주입 | 에이전트의 프롬프트·사고에 정책을 입힌다 | 서브에이전트를 띄울 때 프로파일별 정책 텍스트를 system prompt에 넣음 |
| 단계 선택 | 엔진 안에서 필요한 단계만 조합 | gate만 / policy+gate / 전체 |

## 장치가 되는 것과 안 되는 것

이 재정의에서 먼저 갈라야 했던 것은 "무엇을 장치로 만들 수 있는가"였다.

| 층 | 재사용 가능한 것 | 재사용 안 되는 것 |
|---|---|---|
| L3 gate, L4 eval | 전부. 스크립트라 하네스·모델 무관 | — |
| L0 policy | 텍스트 블록 | 주입 방식과 **효과** |
| L1·L2 skill | 지시문 패키징 | 동작 결과. 모델 버전과 컨텍스트 상태에 따라 달라짐 |

여기서 나온 핵심 통찰:

> **LLM 계층은 프롬프트 텍스트가 재사용되는 게 아니라, 그 텍스트가 여전히 효과가 있는지 확인하는 테스트가 재사용된다.**

그러므로 프롬프트 층의 장치화는 텍스트 + 계약 + 회귀 테스트 세 개가 한 묶음일 때만 성립한다. 텍스트만 떼어 옮기면 그건 장치가 아니라 복사다.

## 장치로 만들 수 없다고 인정한 것

- **모델 드리프트.** 모델이 바뀌면 L0·L1·L2는 재인증 대상이다. 재인증을 자동화(eval을 모델 버전별로 실행)할 수는 있지만 없앨 수는 없다.
- **priming 희석.** 긴 세션에서 정책 효과는 감쇠한다. 장치가 할 수 있는 건 산출물 경계에서 **감지**하고 **재주입**하는 것뿐이다. 이건 하네스 설계 문제이지 패키징 문제가 아니다.
- **판정자 순환.** LLM이 LLM을 채점하는 구조는 다른 모델을 쓰거나 사람 표본을 섞어 완화할 뿐 제거되지 않는다.
- **맞춤법 외부 의존.** hanspell 계열은 외부 API에 기대므로 오프라인·CI에서 불안정하다.

## 1차 답에서 살아남은 것

형태는 바뀌었지만 다섯 설계 결정은 그대로 다음 단계로 넘어갔다.

| 1차 답의 결정 | 엔진에서의 모습 |
|---|---|
| sidecar report가 층 사이의 유일한 데이터 | Response의 `report` 필드, `core/report.schema.json` |
| gate는 CLI + exit code 계약 | `ko.gate` capability (tool) |
| 정책은 블록 합성으로 렌더링, 해시 기록 | `policy` prompt 단계, `policy_hash` |
| 업스트림은 fork 없이 lock으로 고정 | `vendor/` + `vendor.lock` |
| 단계 활성화 자체를 eval로 gate | preset 승격 조건 |
