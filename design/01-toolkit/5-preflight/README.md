# 5-preflight — 구현 흐름 정의

구현 전에 검증과 구체화를 끝내는 단계입니다. 사용자와 상호작용하는 마지막 단계이고, 여기서 정한 흐름이 받아들여지면 구현(6-build)은 멈추지 않고 자율적으로 끝까지 갑니다.

## preflight가 만들어야 하는 것

1. **예상 흐름.** P마다 순서, 만드는 파일, 확인 방법, 끝나는 조건. 06 §14를 실행 가능한 수준으로 구체화한다.
2. **미리 정한 결정.** 06 §16.2의 열린 결정 중 preflight에서 답할 수 있는 것은 여기서 답한다. 구현 중에 답할 것은 판단 기준(최선 / 되돌리기 싼 것, 탐색 방법)을 적어 둔다.
3. **사전 검증.** 흐름이 기대는 가정을 독립 서브에이전트로 확인한 기록. P0의 파일 지도와 문서 검토가 그 첫 부분이다.
4. **release를 막는 조건.** 구현은 멈추지 않는다. 대신 어떤 상황이 master 머지를 막는지 미리 열거한다 — 스펙의 대안까지 실패한 메커니즘, 도달하지 못한 완료 기준, 라이선스 불명. 구현은 그 상황에서 되돌리기 싼 경로로 계속 가고 기록에 release-blocked 표시를 남긴다. 머지 여부는 7-review에서 정한다.

구체화의 깊이는 사용자와 함께 조절합니다. 너무 얕으면 구현이 되돌리기 싼 경로로만 가며 release-blocked가 쌓이고, 너무 깊으면 스펙을 다시 쓰는 일이 됩니다.

## 이 단계가 끝나면

`flow.md`를 사용자가 받아들이면 `dev`에서 P1을 시작합니다. 구현 기록은 `../6-build/`에 P마다 쌓입니다. 06b의 P1 이후 절은 거기에 씁니다 (이 파일의 머리말은 "P 단계마다 절을 덧붙인다"고 했으나 프로세스가 바뀌어 여기서 끝납니다).
